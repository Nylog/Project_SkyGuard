# Project_SkyGuard
---

SkyGuard is an autonomous system built for Celestial Line's central operations,
designed to classify incoming operational messages (from pilots, ground staff,
and passengers) and respond based on their category and the
requester's role.
 
The system combines a fine-tuned BERT classifier, a local LLM-powered agent
with real tools (flight database, live weather, baggage tracking, fuel
calculation, seat information), and a full Flask web application with
role-based authentication.

---

## What it does

Incoming messages are classified into three categories:
 
- **SOS** — critical emergencies (fire, hijacking, medical emergency, structural failure)
- **MAINTENANCE** — technical or logistic issues requiring ground support
- **SERVICE** — routine passenger requests and general questions

Access to each category depends on the user's role:
 
- **guest** — can only access SERVICE requests (baggage, seat info, general questions).

- **admin** — can access all categories, including SOS and MAINTENANCE, and admin-only tools like fuel calculation.

Authorized messages are handled by an AI agent that can call real tools to
answer with actual data, rather than guessing.

---

## Agent tools

| Tool | What it does | Access |
|---|---|---|
| Flight status | Looks up a flight's route, schedule, and status, enriched with real-time weather at departure/destination and readable city names | guest / admin |
| Lost baggage report | Registers a lost baggage report for a flight and returns a reference number | guest / admin |
| Baggage status check | Checks the status of a previously registered baggage report | guest / admin |
| Seat amenities | Checks whether a seat has USB, power outlet, or TV, and its position (window/aisle/middle) | guest / admin |
| Fuel load calculation | Estimates fuel needed for a flight based on distance and passenger count | **admin only** |



The agent also has **conversation memory**: it uses the last couple of user
messages as context when classifying a message (so short follow-ups like
"the flight was SK315" are understood correctly), and the full session
history when generating its response.

---

## Architecture

- **Classifier**: `bert-base-uncased`, fine-tuned on a custom dataset of
  labeled phrases (SOS / MAINTENANCE / SERVICE), built through a
  combination of manual writing, AI-assisted generation.
- **Database**: SQLite, storing fictional flights (Celestial Line), user
  accounts with hashed passwords, baggage reports, and a simplified seat map
- **Agent**: built with LangGraph, powered by a local **Qwen2.5:7b-instruct**
  model via Ollama — no external API required, everything runs offline.
- **Weather**: real-time data from the [Open-Meteo](https://open-meteo.com) API (free, no API key).
- **Backend**: Flask, with session-based authentication (hashed passwords, `werkzeug.security`).
- **Frontend**: plain HTML/CSS/JavaScript, single-page chat interface.

## Requirements
 
- **Python 3.12**
- [**uv**](https://docs.astral.sh/uv/) for dependency and environment management
- An **NVIDIA GPU with CUDA support** (recommended, for fast model training/inference — the project also runs on CPU, just slower)
- [**Ollama**](https://ollama.com) installed locally
---


## Setup

### 1. Clone the repository

```powershell
git clone <repo-url>

cd Project_SkyGuard
```

### 2. Install Python dependencies

```powershell
uv sync
```

### 3. Install Ollama and pull the local model

Download and install Ollama from [ollama.com](https://ollama.com), then:
 
```powershell
ollama pull qwen2.5:7b-instruct
```

### 4. Generate the database
 
```powershell
uv run python db/seed_flights.py
uv run python db/seed_users.py
uv run python db/seed_seats.py
```

This creates `data/flights.db` with fictional flights (with dates always
relative to when the script is run), demo user accounts, and a seat map.


### 5. Get the classifier model
 
A pre-trained model is expected in `models/bert_classifier/`. To generate it
yourself, run the full training notebook:
 
```
training/SkyGuard_Classifier_training.ipynb
```
 
This loads the dataset from `data/raw/`, fine-tunes `bert-base-uncased`, and
saves the resulting model automatically.


### 6. Start the app
 
```powershell
cd backend
uv run python app.py
```
 
---

### 7. Open the app

Go to: http://127.0.0.1:5000 in your browser.

Alternatively, you can open `backend/static/index.html` directly — the page
will automatically detect this and redirect you to the correct address,
since login and chat only work through the Flask server.
